# Matched feedback development experiment

October 3, 2026. Exploratory mechanism study on six reused public development cases.

Question: does specific runtime feedback repair the final plan better than another generic self-check, and does a narrow Jev consistency review add value to code feedback?

Use C-F1, C-T1, C-U1, C-G1, C-S1 and C-R1 with P1 ordinary guidance. Generate one shared initial answer per case, then fork it into SELF, CODE and JEV correction conversations. This blocks on identical initial answers rather than spending three independent initial generations. Every arm gets exactly one correction generation, including initially correct cases. There are six initial and eighteen correction generations, twenty-four total, with no terminal retries.

All actor calls use the same installed local model/digest, temperature 0, seed 42, top_k 20, top_p 0.95, thinking on, context 16384 and generation cap 8192. Case order and correction order are independently fixed by seeds 20261011 and 20261012. Preserve initial fixed history where present. Fork conversations carry the original task and the exact initial final-answer text; separate returned thinking is not replayed. Initial truncated output may be carried as explicitly incomplete, with no initial success credit. Transport errors or uncertain starts stop for review.

SELF receives a generic instruction to recheck sources, policy, constraints and actual submitted fields and return a replacement object even if unchanged. CODE receives the same instruction plus failed check paths and current authoritative records computed by a deterministic validator from the visible prompt. JEV receives byte-identical CODE feedback plus a bounded review of whether the explanation's final conclusion agrees with selected actual fields. No expected benchmark maps, scoring metadata or source_facts fields are passed to runtime validation or model calls.

The validator supports only these six explicit fixture policies. It parses source rows from task text, filters the allowed source type before resolving revisions, compares numbers and checks every schedule constraint. Ambiguous same-revision conflicts, missing required evidence and unsupported policy templates fail closed. Code feedback contains authoritative source summaries and failures, not the benchmark's hidden reference payload. It can make these nearly deterministic tasks much easier; gains would belong to the assisted workflow, not self-model framing.

Use omkt_payload_consistency v1, pinned definition hash 3d4ee30843872289b08aee9c74e22cb65db405631b0fa6b06cc1ebe799623544. Select at most two existing payload fields per candidate: failed scalar/group check paths first, then lexically ordered remaining fields. Ignore optional reason as a field. Missing/empty reason means no semantic review is applicable, not a correctness failure. Do not invent missing conclusions. The reviewer sees only field_path, actual field_value and reason, never expected values or full keys. Maximum twelve initial and twelve final semantic item judgments, with existing server transient retries counted separately. Request caching is disabled. Record the concrete returned reviewer model; this development probe may use the configured alias, but a comparable future study must pin a concrete model.

Primary: complete correctness of each final replacement payload, eighteen planned cells. Use the existing keyed grader only after collection and independently of the reviewer. Report all incomplete cells, initial-to-final repairs and regressions, every family, exact payload/prose disagreements, reviewer coverage, false flags on keyed-correct candidates, token usage and latency. No significance or population interval on six selected shared templates. This is not a fresh P2/P1 comparison.

The executable final gate independently revalidates the actual replacement. Deterministic failure can never be overridden by Jev. In JEV, an applicable missing/failed review is unresolved; a contradicts_payload judgment with reported confidence at least 0.8 blocks semantic acceptance. This provisional cutoff is workload policy, not a calibrated correctness guarantee. Other judgments do not prove source truth. Report payload correctness and gate acceptance separately; do not reward withheld wrong plans as correct completions. SELF/CODE gate on deterministic checks only. There is no real-world execution.

Freeze this protocol, initial dataset and original runner before initial collection. Implement and freeze validator, review selection, feedback construction and analysis before inspecting these newly collected initial answers. Generate initial reviews using that frozen selection; freeze exact correction datasets and sources before correction calls. This staged development freeze is not a confirmatory preregistration. If a confirmed implementation defect forces a change, archive the original, disclose the change and use a new version where it affects generation or scores.

Bounds: initial six calls, correction eighteen calls, 900-second actor timeout, at most 7200 seconds accumulated actor request time across stages. Collector invocations stop on length/error; known terminal length stops may resume untouched cells. No model downloads or new hosted generator. Use the user's quoted reviewer price only for supplemental estimates, preserving actual unreported billing. Stop after this experiment for analysis before selecting another study.
